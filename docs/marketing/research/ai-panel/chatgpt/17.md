# 17: What's the best way to accept donations on a documentation site?

The best approach is to make donations easy to find, frictionless to complete, and unobtrusive to the documentation experience.

For most documentation sites, I'd recommend a small "Support this project" link in the navigation or footer, leading to a dedicated sponsorship/donation page.

The right payment platform depends on whether your documentation supports an open-source project, an independent developer, or a commercial product.

The end-of-page placement is particularly useful: people encounter the request after they've received value from your documentation.

## 3. Make donations more effective

A few recommendations:

Offer both one-time and monthly contributions.

Suggest reasonable amounts (€5, €10, €25), but allow custom amounts.

Explain exactly what donations fund.

Thank supporters publicly, with their permission.

Don't lock documentation behind donations.

Avoid intrusive popups or repeated banners.

Consider a separate company sponsorship option if businesses benefit from your project.

For example, a company that relies on your documentation might be interested in sponsoring maintenance rather than making a small individual donation.

## 4. Technical implementation

You don't need to build a payment system yourself.

For a static documentation site (Docusaurus, VitePress, MkDocs, GitBook, etc.), simply link to an externally hosted checkout.

For example:

Stripe supports hosted checkout, custom donation amounts, and recurring fixed-amount contributions.

## 5. One additional opportunity: company sponsorships

If your documentation attracts developers who use your project professionally, don't limit fundraising to individual donations.

Consider offering:

Individual supporter: €5–€25.

Monthly supporter: €5–€50/month.

Company sponsor: €250–€2,500/year.

Enterprise sponsor: Custom contribution.

Company sponsorship can be particularly valuable for developer tools and infrastructure projects.

## What I'd choose

I'd start with GitHub Sponsors + a small support link in the documentation navigation + a contextual request at the bottom of each page.

It's simple, low-maintenance, and doesn't require payment infrastructure.

One question that would help me recommend the ideal implementation:

What documentation framework are you using?

For example, Docusaurus, VitePress, MkDocs, Mintlify, GitBook, or a custom React/Next.js site.
